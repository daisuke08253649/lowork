# T2-3 実装サマリー

## タスク

T2-3: 普通のチャット画面の統合

## 実装内容

- `NormalChat`にモデル取得・選択、入力、送信、会話中画面への切り替えを実装
- Axiosのfetchアダプターで`POST /normal-chat`のSSEを受信し、トークンごとにAIメッセージを更新
  - ストリーミング専用リクエストは`timeout: 0`で共有クライアントの5秒タイムアウトを無効化
  - HTTPエラーとSSE内エラーを日本語のエラー表示へ反映
- Zustandの`chatStore`にメッセージ・ストリーミング状態・エラー状態を追加
- メッセージ型を`src/types/chat.ts`へ切り出し、コンポーネントとストアで共有
- メッセージ一覧は、ユーザーが最下部付近にいる場合のみ新着メッセージへ追従するように変更
- ライブリージョンを最新のAIメッセージ単位へ移し、ストリーミング完了後に読み上げるように変更
- ストリーミング中は「新しいチャット」操作を無効化し、進行中の応答と状態が競合しないようにした

## レビュー指摘への対応

- Axiosのストリーム型エラー本文を読み取り、バックエンドの`detail`をUIに表示するようにした。接続不能時は日本語の固定メッセージを表示する
- SSEのJSON・スキーマ検証失敗を「応答の解析に失敗しました」に統一した
- 終端区切りが欠けた最後のイベントを処理し、`done: true`未受信で終了した場合はエラーにするようにした
- SSEリーダーをキャンセルしてロックを解放し、イベント抽出処理を関数へ切り出して制御構文のネストを2階層以内に収めた
- 送信開始時はスクロール追従を再有効化し、失敗時は入力本文を復元するようにした
- ストリーミング完了時の読み上げは、常時有効な非表示のライブリージョンへ確定本文を設定する方式に変更した

## 再レビュー指摘への対応

- 送信失敗時は、その送信で仮追加したユーザー・AIメッセージをストアから取り除くようにした。入力本文は復元されるため、空のAIバブルや重複メッセージを残さず再送できる

## 承認後の任意改善

- ストリーム中に一部でもAI回答を受信してから失敗した場合は、その回答とユーザーメッセージを保持するようにした。この場合は重複再送を避けるため入力本文を復元しない
- HTTPエラーは詳細メッセージを持つ新しい`Error`を生成し、Axiosの元エラーと異なるメッセージがスタックへ残る問題を解消した
